# 设计文档:Finder 右键「移动到…」快速操作

- 日期:2026-07-21
- 状态:已与用户确认设计,待写实现计划
- 目标平台:macOS 26.5.2 (build 25F84),Apple Silicon (arm64),系统语言简体中文

## 一、背景与目标

用户希望在 Finder 右键菜单中获得一个"把选中文件直接移动到指定文件夹"的功能,并满足以下硬性约束:

- **零第三方软件**:不安装任何应用,不依赖后台常驻程序。
- **开机即用**:重启后依然可用,不需要打开任何程序。
- **纯原生**:只使用 macOS 自带能力。

经过方案对比,放弃了"剪切 + 粘贴 + 颜色标签提示"的两段式路线(涉及剪贴板状态、粘贴键 ⌘V/⌘⌥V 之争、剪切态可视化等复杂问题),改为一步到位的「移动到…」快速操作。

## 二、范围

**本次实现:**
- 一个名为「移动到…」的 macOS 快速操作(Quick Action / Automator Service)。

**明确不做(本次范围外):**
- 删除 Finder 右键的「复制 / Duplicate(⌘D)」项。原因:macOS 未提供关闭内置右键菜单项的正规方式,唯一途径是关闭 SIP 修改系统或安装第三方菜单管理工具,前者属于改动系统安全设置(不做),后者违反零软件约束。列为以后单独议题。
- 剪切/粘贴两段式操作、剪切态颜色标签提示。

## 三、方案设计

### 3.1 架构

一个 macOS 原生「快速操作」(Automator Service 工作流),安装到 `~/Library/Services/`。系统右键菜单会自动在「快速操作」子菜单中显示「移动到…」。

- 纯原生,零第三方软件。
- 由系统按需加载,无后台常驻进程。
- 重启后依然存在,开机即用。

### 3.2 交互与数据流

1. 用户在 Finder 中选中一个或多个文件/文件夹。
2. 右键 → 快速操作 →「移动到…」。
3. 弹出系统文件夹选择框(AppleScript `choose folder`)。
4. 用户选定目标文件夹。
5. Finder 将选中项**移动**(非复制)到目标文件夹。

### 3.3 错误处理

- **用户在选择框点"取消"**:静默退出,不做任何操作。
- **目标存在同名文件**:交由 Finder 原生处理(替换/保留提示)。
- **移动失败**(权限不足、卷只读等):弹出提示框显示失败原因。
- **未选中任何项目**:快速操作在无选中项时不触发/不显示,无需额外处理。

### 3.4 实现要点(供实现计划参考)

- 快速操作内部使用「运行 AppleScript」动作。
- 核心逻辑(伪代码):
  ```
  set dest to choose folder with prompt "移动到哪个文件夹?"
  tell application "Finder" to move input to dest
  ```
- 输入类型:接收 Finder 中选中的文件/文件夹(files/folders)。
- 工作流以 `.workflow` bundle 形式手工构建(`Contents/Info.plist` 声明 NSServices + 菜单名「移动到…」,`Contents/document.wflow` 定义 AppleScript 动作),不依赖打开 Automator GUI。

### 3.5 交付与安装

在 `~/claude/finder-move-to/` 建立项目目录,包含:

- 快速操作工作流源文件(`.workflow` bundle)。
- 安装脚本:将工作流拷贝到 `~/Library/Services/` 并刷新服务缓存(`/System/Library/CoreServices/pbs -flush` 或重启 Finder)。
- 卸载/说明文档。

用户自行运行安装脚本完成安装。

## 四、验证方式

因属图形界面操作,以手动验证为主:

1. 先用 `osascript` 在终端单独运行 AppleScript 移动逻辑,确认移动行为正确(源消失、目标出现、为移动非复制)。
2. 安装工作流后,在 Finder 中建立测试文件,右键运行「移动到…」,确认:
   - 菜单项出现在「快速操作」子菜单;
   - 单个文件移动成功;
   - 多个文件一次移动成功;
   - 取消选择框时无副作用。
