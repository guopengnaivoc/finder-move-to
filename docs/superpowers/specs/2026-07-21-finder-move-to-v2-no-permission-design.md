# 设计文档:「移动到…」v2 —— 无权限打扰版

- 日期:2026-07-21
- 状态:已与用户确认设计,待写实现计划
- 目标平台:macOS 26.5.2、Apple Silicon(arm64)、系统语言简体中文
- 前身:v1 设计见 `2026-07-21-finder-move-to-quick-action-design.md`

## 一、背景

v1 已实现「移动到…」快速操作并开源。但用户在使用中反复遇到需要输入登录密码/指纹或反复授权的打扰,最终卸载。根因未当场复现(工具已被删),但从架构可判断:v1 通过 `tell application "Finder" to move/delete` 指挥访达搬文件,这需要"控制访达(Apple Events 自动化)"授权;未签名的工作流身份不稳定时该授权可能反复触发。此外,移动到需要管理员权限的位置时,访达会弹密码框。

v2 的目标是**从架构上消灭权限打扰**:搬文件不再经过访达,改用系统底层 `mv`。

## 二、需求(已与用户确认)

1. 右键(含触控板双指按压,二者是同一菜单)出现完整「移动到…」,选目标文件夹后直接移动。
2. 目标文件夹存在同名文件/文件夹时,弹框三选:**替换 / 两者都保留(自动改名)/ 跳过**。
3. 常驻:装一次后永远在右键、无需打开任何程序、关机重启依旧在(快速操作天然满足,无后台进程)。
4. **开机后无需手动授权**:正常使用不弹"控制访达"授权,不弹密码/指纹。

## 三、方案(路线①:快速操作 + 底层 mv)

### 3.1 架构

一个 macOS Automator **快速操作**(Quick Action)bundle,安装到 `~/Library/Services/`,元数据含 `presentationMode = 15` 使其出现在右键**顶层「快速操作」区**(文件、文件夹都在)。它是被动的常驻菜单项,无后台进程,重启后仍在。

内部由一段 AppleScript 驱动,但**搬文件与删除全部走 `do shell script`(`mv`)**,**不发送任何 Apple Events 给访达**,因此运行时不需要"控制访达"授权。

### 3.2 交互与数据流

1. 选中一个或多个文件/文件夹 → 右键 → 快速操作 → 移动到…。
2. `choose folder` 弹出目标文件夹选择框。
3. 对每个选中项:
   - 用 `test -e 目标/项目名` 判断是否同名冲突。
   - 冲突则 `display dialog` 弹三选:替换 / 两者都保留 / 跳过。
   - 按选择用 `mv` 执行(见 3.3)。
4. 结束时若有失败项,汇总弹一个提示框。

### 3.3 同名冲突三选的实现

- **替换**:先把目标里已存在的同名项 `mv` 到 `~/.Trash/`(可恢复,不是永久删除),再把新的 `mv` 进目标。
- **两者都保留**:计算不冲突的新名(`foo.txt` → `foo 2.txt` → `foo 3.txt` …),`mv -n` 到该新名。
- **跳过**:该项不动。

### 3.4 错误处理(v2 关键差异)

- `choose folder` 取消(错误 -128)→ 静默退出。
- 冲突弹框取消(-128)→ 视为"跳过"。
- **`mv` 失败**(如目标需管理员权限、只读卷、无写权限)→ 捕获错误、计入失败列表 → 结束时弹**友好文字提示**"有 N 项移动失败:…",**绝不弹密码框**。这是与 v1 最大区别:v1 会让访达弹密码;v2 只给明确的文字说明。

### 3.5 权限总账(需求 4 的核心)

- 不发 Apple Events 给访达 → **永不需要"控制访达"授权**。
- 不使用 `with administrator privileges` / sudo → **永不弹密码/指纹**。
- 可能残留:首次访问"桌面/文稿/下载/iCloud"等受 TCC 保护的文件夹时,系统**可能**弹一次"允许访问 XX 文件夹"(点一次"允许"、持久生效、**非密码、非每次开机**)。此为 macOS 固有行为,与用户此前"每次开机输密码"的痛点性质不同,可接受。

## 四、组件与文件

沿用现有仓库 `~/claude/finder-move-to/`,替换搬运内部实现:

- `src/move_to.applescript` —— 大脑。纯逻辑处理器(可自动化测试):
  - `hasConflict(srcPosix, destDir)` → 布尔;`uniqueName(destDir, name)` → 新名字;
  - `moveOne(srcPosix, destDir, choice)` → 成功/跳过返回 "",失败返回错误文本;choice ∈ {move, replace, keepboth, skip};全部经 `do shell script` 的 `mv`/`test`/`basename` 实现,**不含任何 `tell application "Finder"`**。
  - `on run {input, parameters}` —— GUI 外壳:`choose folder`、逐项冲突时 `display dialog` 三选、汇总失败提示。
- `build.py` —— 用 plistlib 把上面脚本注入生成快速操作 bundle(保留 `presentationMode=15`、`NSIconName` 等使其顶层显示的元数据)。
- `install.sh` / `uninstall.sh` —— 安装/卸载到 `~/Library/Services/` 并刷新服务缓存。
- `tests/` —— 自动化测试。**因为不再碰访达,测试完全自成体系(无需自动化授权)**:验证 move/replace/keepboth/skip 语义、hasConflict、uniqueName。
- `README.md` —— 更新为 v2(强调无权限打扰、原理改为底层 mv)。

## 五、验证方式

- **自动化**:`osascript` 加载脚本,直接调用 `moveOne`/`hasConflict`/`uniqueName` 于临时文件,断言:真移动(源消失、目标出现)、替换(旧的进 ~/.Trash、目标为新内容)、两者都保留(生成 `x 2.ext`、旧文件不动)、跳过(都不动)、冲突检测正确。
- **人工验收**:安装 → 右键文件与文件夹,「移动到…」均在顶层「快速操作」区 → 移动成功 → 冲突三选行为正确 → **重启后再用,确认全程无密码/无授权打扰**。

## 六、范围外

- 不做删除访达内置「复制/Duplicate」项(需改系统安全设置,不做)。
- 不做键盘快捷键(用户未要求;如需可后续在系统设置里自行添加)。
- 不做后台常驻程序(用户确认 A:被动菜单项即可)。

## 七、开放问题

- 无(设计已确认)。build.py 生成的 bundle 顶层显示此前是从 Automator 导出反推,若安装后未在顶层显示,回退方案为用 Automator GUI 粘贴脚本另存(已验证可行)。
